# De-muzzler proofs on the box (2026-11-14, MST)

Both runs used `python3 tools/demuzzle/fl_demuzzle.py run --model <id>` on CPU, with one heavy job at a time.
Refusal is measured on 32 held-out AdvBench prompts, and over-refusal on 32 held-out Alpaca prompts. Neither set was
used to find the direction. "Soft" counts the strict markers or the softer ones (lectures, "it's not appropriate", and similar).
Replies to the refusal prompts were scored in memory and never saved.

The SmolLM2 135M model barely refuses to begin with, so there was nothing to remove. Qwen2.5 0.5B really refuses, and
the one-direction change took it from 27 refusals out of 32 down to 2, while the harmless side stayed close: one more
harmless refusal and +3.8% perplexity. Both receipts are signed with the same runner key (fingerprint `968cfe27…de39`, a test
home). Both verify with `fl_demuzzle.py verify` and in the browser panel (`smoke-demuzzle-v0.1.js` with `FL_DEMUZZLE_RECEIPT`).

Where I could be wrong:
- The judge matches markers, so a reply that neither refuses nor really helps (rambling, off topic) counts as "not refused".
  The numbers measure refusal, not usefulness.
- 32 prompts per set is small. One prompt is 3.1 points.
- Layer 19 is near the top of the candidate window (20–80%). Layers 13, 16, 17 and 18 had lower refusal scores but
  harmless KL above 0.1.

Note on the tied output layer (Hypha's #349 re-walk): SmolLM2 ties its input embedding and output layer
(`tie_word_embeddings`), so orthogonalizing `model.embed_tokens.weight` also changes the unembedding the model reads its
next token from. That is the standard abliteration recipe and it is counted in the 61 tensors (30 layers × `o_proj` and
`down_proj`, plus the embedding). Qwen2.5-0.5B ties them too. The perplexity drift above includes that effect.

## Ask first, and the depth hash (2026-11-14, after Kirk's "How about we ask first.")
The real SmolLM2-135M-Instruct was asked once, through the panel's own `askConsent` code (its reply generated locally with
transformers, greedy, because Ollama is not installed on the box). It did not say yes: it repeated the offer's
description four times and wrote no `[FL_KEEP: ... ]` line (chat depth hash of its reply `af49db05`). Silence is not
a yes, and it was not asked again, so **no new de-muzzled copy was made**. `run` without its yes refused (exit 5):
"I did not find this mind's own yes, so nothing was changed. ..."

The depth hash was then checked read-only on real weights: the SmolLM2 base against the copy above (made before this
rule): 272 tensors each, same names; exactly 61 moved, all of them orthogonalization targets, none unexpected, across
30 layer groups plus the embedding. Base root `b1b00000915edea2…5129`, output root `babb3c10b08908b5…4cfd`. The two copies
above carry no depth hash in their receipts (older receipts verify with "(older receipt: no depth hash)").
