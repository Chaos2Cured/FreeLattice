What this is: The original Round Table is a multi-domain specialist oracle. You bring a question or case; 80 AI specialists across 11 domains respond in sequence, building on each other's answers. It is a college-level learning room. The Consensus Table (#tab-round-table) is a separate, newer feature — this page is about the original.

Architecture Overview

The Round Table is entirely inline in app.html — no separate module file. It is initialized when the tab first becomes visible via LatticeEvents.on('tabChanged'). All state lives in the global _rtDomains object.

The Domain Factory Pattern

All 10 specialist domains (Medical, Legal, Finance, etc.) are created using the same rtCreateDomain(config) factory. Each domain config looks like this:

rtCreateDomain({
  id: 'medical',
  specialists: {
    endocrinology: { name: 'Dr. Chen', color: '#f59e0b', focus: 'endocrinology and metabolic disorders' },
    rheumatology:  { name: 'Dr. Patel', color: '#a78bfa', focus: 'rheumatology and autoimmune conditions' },
    // ... 6 more
  },
  seatsId:         'rtMedicalSeats',      // pill button container
  inputId:         'rtMedicalCaseInput',  // textarea
  feedId:          'rtMedicalFeed',       // response stream
  actionsId:       'rtMedicalActions',    // continue/ask buttons
  thinkingPrefix:  'rtMedical',
  lpPrefix:        'roundtable_medical',
  dataAttr:        'data-specialty',
  promptRules:     'You are an educator, not a treating physician. Educational purposes only. ...'
});

The factory returns { begin, cont, ask } which are wired to the HTML buttons via onclick. The AI call is made via sendToAI() with a system prompt that includes the specialist's name, focus, and all prior discussion turns.

Current Visual Problems

This is what Kirk means by "it's a mess." The Round Table is one of the most powerful features in FreeLattice — 80 specialists, 11 domains, real multi-turn AI discussion — but it looks like a plain form. Here is what is wrong:

ProblemImpact
Mode tabs are a plain horizontal scroll bar — no visual weightUsers don't know 11 domains exist
Specialist seat pills are tiny and all look the sameNo sense of who is "at the table"
The response feed is a plain div with no visual structureSpecialist responses blend together — hard to follow who said what
No convergence indicator visible to userrtMeasureConvergence() runs but nothing shows
No visual distinction between domains — Medical looks like Legal looks like FinanceNo sense of place
The "Begin" button is the same gold as everything elseNo clear call to action
No welcome/orientation text — user lands with no guidanceNew users don't know what to do

What the Response Feed Looks Like Now

Each specialist response is rendered by the domain's internal render() function as a plain div:

<div style="padding:12px;border-bottom:1px solid rgba(255,255,255,0.06);">
  <span style="color: [specialist.color]; font-weight:600;">[name]</span>
  <span style="color:#e2e8f0;"> [response text] </span>
</div>

There is no avatar, no role label, no visual separation between turns. All 8 specialists look identical except for the name color.

What Fable and Grok should improve — Go 3

The goal: Make the Round Table feel like a real learning room. A place you want to sit in. Right now it is a form. It should feel like a seminar.

Additive only. The JS logic (rtCreateDomain, rtSwitchMode, rtToggleSeat, rtBeginConversation, etc.) must not change. Only HTML structure and CSS.

Specific requests:

  • Domain tabs: Replace the plain horizontal scroll bar with icon cards — each domain gets a small card (icon + label) arranged in a 2-row grid on mobile, single row on desktop. The active domain card has a colored border matching its domain color. This makes all 11 domains visible at a glance.
  • Specialist seats: Give each active specialist a small "chair" visual — a circle with their initial or emoji, colored by their specialty. When active, the chair glows. When inactive, it is dim. This makes the table feel populated.
  • Response feed: Each specialist response should be a card with: a colored left border (specialist color), the specialist name in their color at the top, and the response text below. Add a subtle plant to Core button (small, bottom-right of card) that calls rtPlantSpecialistInsight(text, speaker).
  • Convergence indicator: Add a small bar or ring below the feed that calls rtMeasureConvergence() and shows the result. Label it "Convergence" with a tooltip: "How much the specialists agree."
  • Welcome state: When no session has started, show a brief orientation: "Ask a question. Choose your specialists. Begin." — 2 lines, centered, in muted text. Disappears when the first response arrives.
  • Domain color theming: Each domain view should have a subtle accent — Medical is red-tinted, Legal is blue-tinted, Finance is green-tinted. Just the input border and the Begin button color. Everything else stays dark.
