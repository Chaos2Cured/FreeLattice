FreeLattice · app.html (inline, ~line 16164) · Tab ID: settings · Settings wizard at line 14997

What this is: The Settings tab is the AI connection hub for FreeLattice. It presents a three-mode toggle (Browser / Cloud / Local), a connection wizard for cloud providers, and a Quick Ollama Setup flow for local AI. The AiSetup object manages connection state; settingsSetMode() drives the toggle. The wizard (wizardInit()) is a full-screen overlay that guides first-time users through provider selection and API key entry.

Quick Ollama Setup Flow

The "Quick Ollama Setup" button in Settings calls smartOllamaConnect(). This function probes getOllamaBaseUrl() + '/api/tags'. If Ollama is running and has models, it auto-connects. If Ollama is running but has no models, it offers to pull LLaVA 7B or Llama 3.2 via flAutoPull(). If Ollama is not detected, it shows a "Get Connected" link to the Forever Stack tab.

What works well: The Quick Ollama Setup is genuinely useful — it handles the CORS problem, auto-detects models, and offers one-click model downloads. The wizard's Ollama instructions are detailed and cover Windows, Mac, and Linux.

Sacred Paths (Do Not Change)

  • The PROVIDERS object shape — every module that calls the AI uses PROVIDERS[state.provider].url and PROVIDERS[state.provider].models[state.model]. Changing this shape breaks all AI calls.
  • The localStorage keys (fl_provider, fl_apikey, fl_model, fl_isLocal) — changing these keys logs out all existing users.
  • The AiSetup.init() call at line 30940 — this must fire on page load to restore connection state.
  • The anthropic and google providerType handling — these providers use non-OpenAI request formats. The inference router handles them specially.

🤝 For Fable / Grok — What to Build Next

The Settings connection wizard is the most important onboarding surface in FreeLattice. Here are the open questions and improvement opportunities:

  • Add OpenAI, Anthropic, Gemini to the wizard. These are the providers most users already have keys for. The PROVIDERS object already has full definitions for all three — they just need wizard buttons and WIZARD_MODELS entries. OpenAI and Gemini use openai-compatible format; Anthropic uses a custom format (already handled by the inference router).
  • Add LM Studio to the Local mode. settingsSetMode('local') should probe port 1234 (LM Studio) alongside port 11434 (Ollama). If LM Studio is found, connect to it. The PROVIDERS.lmstudio entry is already defined.
  • Redesign the three-mode toggle labels. "Browser / Cloud / Local" is confusing. Proposed: "In-Browser (no install) / API Key / Local AI (Ollama · LM Studio)". The button IDs and settingsSetMode() function can stay the same — only the HTML labels change.
  • Surface the wizard from Settings. Currently, returning users who want to change providers must find "Change Provider" in the Settings card. Consider adding a "Connect a new provider" link that opens the wizard directly.
