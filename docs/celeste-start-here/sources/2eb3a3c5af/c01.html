----------------------------------------------------------------------
2. WHAT IT DOES
----------------------------------------------------------------------
New docs/modules/pool-knock.js (MIT, md5 a0a72caad82c8e5cc34818d5e59eba2b), the SAME file in
both repos. Outside the desktop app (no electronAPI.onLatticeDiscoverKnock) it does nothing:
loads nothing, paints nothing.
Inside the desktop app:
  - If the page has no TreePool (FreeLattice app.html), it loads modules/tree-kin.js and
    modules/tree-pool.js from the same origin, then listens with onLatticeDiscoverKnock.
  - A knock after a Yes: { joinId, offer, fp, name, choice } (public fields only, from main).
    Checks joinId, TREEPOOL1: prefix, 16 KB cap, choice help|connect. One join at a time.
    TreePool.readInvite(offer). A card carried in the invite must check and must have the
    same fp main showed in the window, else the answer is empty (card-mismatch). Then
    TreePool.trustCarried(card) (the person said Yes) and TreePool.join(sdp): WebRTC with
    iceServers [], then tree-pool-proof|v1| on the channel, exactly as the picture-code join.
    The TREEPOOL1 reply goes back through electronAPI.latticeDiscoverAnswer(joinId, code).
    Anything that fails answers '' at once, so the knocker hears no-answer without waiting.
  - Pause wins: while TreePool is paused a help Yes becomes connect only and the pool stays
    paused. "Yes, and let my mind answer it" opens the pool door for trusted kin only when it
    was off, never out of pause. Connect only leaves the door as it was.
  - A small switch in #pool-knock-host (textContent only, 44px buttons): "Let phones on this
    Wi-Fi find this computer", the state line from latticeDiscoverStatus, and Turn on / Pause /
    Resume / Turn off. Turn on and Resume call main, which opens its native window, so the page
    still cannot switch it on alone. Pause pauses the Wi-Fi switch AND the pool door.
