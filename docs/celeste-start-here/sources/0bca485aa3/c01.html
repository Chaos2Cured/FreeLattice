1. BEHAVIOR (person-facing)
  A. Search indicator in chat
     - Reuse fl_searchEnabled (default ON unless set to 'false').
     - In the chat chrome (near where people already live), show a small clear "Search on"
       or "Search off" state the person can tap to flip. Do not bury the only control in Settings.
     - Keep existing "_Searched the web for ..._" lines. Do not add per-memory-recall lines.

  B. Build trust (one key)
     - localStorage key: fl_chatBuildTrust
     - Values: "auto" | "notify" | "review"
     - DEFAULT when unset: "auto" (AI decides local builds; no review wall).
     - "review" = person looks at each local build before it applies.
     - "notify" = AI builds; person gets a calm notice after important local builds
       (define important as: new file, delete, or > N lines changed — pick N=40 and smoke it).
     - External push / paid / money: still Principle 2 consent every time (unchanged).

  C. First-time ask (once) — family note (Hypha/Weft/Reed) folded in
     - Key: fl_chatBuildTrustAsked = 'true' after the ask.
     - The first time a mind would apply a local build from chat (FILE: / workspace apply /
       bridge patch), if fl_chatBuildTrustAsked is not set, show one calm choice row in chat
       BEFORE applying anything. Plain words, so she knows what "build" means:
         Title: "A mind wants to change files on this device from chat."
         One line under title: "Build means write or update files here (local). Push to the
         net still asks every time."
         [ AI decides ]  — "Applies local changes. You get a short receipt."
         [ Notify on big ones ]  — "Applies, and pings you when a file is new, deleted, or large."
         [ I review each one ]  — "Nothing applies until you tap Apply."
         Quiet line under the buttons (never a second nag): "You can change this later in Settings."
     - Map: AI decides -> "auto". Notify -> "notify". I review -> "review".
     - Never show that row again unless they clear the key or change it in Settings.
     - Durable override must stay findable in Settings (Weft): do not let consent become a
       one-time ghost. Settings control is required smoke.
     - If they Escape / dismiss: treat as "auto" for this session only; do not set Asked
       until they pick (so the ask can return next session) — report which you shipped.
     - After "auto" or "notify" applies: soft receipt in chat ("Built path; tap to look"),
       never a permission dialog storm (Reed). "review" uses preview + Apply, not confirm().

  D. Settings (minimal, do not redesign)

     - Binding writes fl_chatBuildTrust. Changing here sets fl_chatBuildTrustAsked = 'true'.
