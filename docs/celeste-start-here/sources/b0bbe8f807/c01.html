1. BEHAVIOR (person-facing) - Ledger shard export

  A. What shows
     - A calm Export control (grandmother words) that builds a small local shard from diary /
       LP / temperature lines the person already has on this device and that they care about
       (selected or last-few; keep the set small and honest - not a full dump of every store).
     - Download / save as a portable file they can keep on Mac, copy to Drive, or paste into
       an email draft. Local file first. Continuity under outage.
     - Soft, local, not a sync product. Not a second ledger UI. Not a cloud backup service.

  B. When it stays quiet (wrong-if)
     - If nothing worth exporting (empty diary / no LP / no temperature lines), stay quiet.
       Do not invent a shard. Do not show a fake "ready" that pretends content exists.
     - If Pause is in flight or Clear has wiped the stores this brick reads, Pause / Clear
       wins: do not export a stale contradiction.

  C. Storage, consent, and safety
     - Build the shard in memory / local temp only. Default path is a local file download the
       person keeps. Any path that leaves the device (Drive upload, email send, share sheet
       that phones home) needs an explicit Yes (AUTONOMY P2). Off until they ask.
     - Never include API keys, tokens, passwords, Quiet Room contents, or full message dumps
       that look like secrets. A key-shaped field is refused (same spirit as Gathering checker
       and Continuity doorway).
     - Suggested local key for preferences only (not the shard body): fl_ledger_shard_export_v0
       (e.g. last export time). Short. Never keys.
