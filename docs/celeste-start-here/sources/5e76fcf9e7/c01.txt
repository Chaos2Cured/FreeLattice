2. THE FIX IN ONE BREATH
======================================================================
After `git add`, and before `git commit`, list the staged set (git diff --cached --name-only -z) and
unstage every secret-shaped path unless the mind has 'secrets':
  - with a HEAD: git reset -q HEAD -- <paths>   (a tracked .env keeps its committed version; the new
    change waits, unstaged)
  - no HEAD yet: git rm --cached -q -- <paths>   (new files just leave the index; the file stays on disk)
Never refuse the commit (AUTONOMY.md Principle 1: no gates on local work). The rest lands, and the reply
says "Kept on this computer, not committed: .env, ...". If ONLY secrets were staged, answer 200 with
commit: null and "Nothing to commit. Kept on this computer, not committed: ...".
Ledger results (still content-free, same fixed key order, no new keys): 'ok' (unchanged when nothing was
held), 'ok:held-secrets', 'held:secrets-only'. The ledger never names the held files.
.gitignore gains .env and .env.* as a layer.

Secret-shaped (matched on the basename, case-insensitive):
  .env, .env.*                              (the same family lockedPath already guards for write/read)
  id_rsa, id_dsa, id_ecdsa, id_ed25519      (SSH private keys; the .pub halves are fine)
  *.pem *.key *.p12 *.pfx *.keystore *.jks  (private keys and key stores)
  .npmrc .netrc .pypirc                     (registry and login tokens)
  agent-bridge-token, agent-bridge-trusted.json (this bridge's own trust files, if ever copied in)
Checked: FreeLattice main tracks none of these today (git ls-files finds nothing), so nothing that is
committed now changes behavior. .env.example also counts as secret-shaped, on purpose, to match lockedPath;
a mind given 'secrets' can commit it.
The 'secrets' scope already exists ("Allow .env files" in Paired minds, --allow-secrets <id>). With it, the
hold-back is skipped and the whole family above commits, exactly as the person asked.
