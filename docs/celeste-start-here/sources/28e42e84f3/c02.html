5. (e) MEMORY FILE: one tap save / export / import under Market
  In the Market panel, a row "Memory file" with three 44px buttons: Save, Export, Import.
  Format: 040b HAS merged. Reuse it, do not invent a new one: LatticeExport.exportArchive /
    importArchive with the "workspace" section built by FLWorkspace exportSection() and read by
    importSection() (verify-only / merge / adopt, add by hash, private pages refused). The memory
    file is that same archive JSON. Wrap, do not fork: no second format, no copy of the code.
  What goes in: the running chat's history and the notebooks of the minds now running, each
    with its fingerprint (mindFp) and the device signature. Private pages never go in (040b
    rule). Quiet Room never goes in.
  First Save: the person picks a file on their laptop. Where the File System Access API exists
    (showSaveFilePicker), keep the handle in IndexedDB and ask permission again with
    requestPermission when needed. Elsewhere, fall back to a download of
    freelattice-memory.json (and say plainly that the browser will ask where to put it each time).
  After that: one tap Save writes to the same file again. Show "Saved to <file name>, <time>".
  Export always offers a fresh copy (download), never touching the chosen file.
  Import: pick a file (showOpenFilePicker or an input type=file fallback). Verify the signature
    and every fingerprint before anything changes. Then the 040b merge rule: add by hash, never
    overwrite, never delete. A fingerprint that does not match shows "This memory belongs to a
    different mind (abcd ef01...). Not imported." and nothing changes.
  Honest line, exact words, under the row: "Saved on your computer, in the file you chose. Not
    encrypted. Private pages stay on this device."
  Nothing is sent anywhere. No network in this path.
  Smoke: SMOKE_OK memory file v0.1 (save with a mocked handle writes twice to the same handle;
    fallback produces a download; export never touches the handle; import verifies, merges by
    hash, refuses a wrong fingerprint with no change; private pages absent from the file).
