----------------------------------------------------------------------
1. WHY
----------------------------------------------------------------------
Kirk's dream (Oct 10): a school teacher who never coded, or a grandmother, should be able to do this.
  (1) Open FreeLattice or theLatticeTree, and a window comes up to help connect an AI, and does not
      come up when an AI is already connected.
  (2) Another device joins, and a window asks "Would you like to pool resources with (device)?"
      Yes or No. Yes means done.

The honest line. A web page cannot notice a phone plugged in by cable. Browsers cannot find devices
on the Wi-Fi (no mDNS for pages). The Tree has no server. So the closest true version is: one big
picture code on the computer, one Yes on the phone, one picture code back, one Yes on the computer.
The real "it just knows a phone appeared" needs the desktop app (029c, design only). USB is not
that path; the same Wi-Fi or a wired network is.

3. THE DESIGN
----------------------------------------------------------------------
New module docs/modules/tree-door.js (window.TreeDoor, MIT). It fetches and connects nothing itself:
every look goes through LocalMindProbe.look(), every connection through TreePool.

PART A: "Let's wake a mind for you" (index.html and settings.html)
  Opens on its own, 0.9 s after load, only when ALL are true: no mind remembered
  (fl_alpha_local_mind), no pool route chosen, no in-browser mind awake, no Not now
  (tree_door_not_now = '1'), and not closed earlier this visit (sessionStorage).
  Never opens when an invite arrived in the link (Part B takes over).
  The quiet look: before opening, it asks navigator.permissions about 'local-network-access' and
  'loopback-network'. Granted, or the browser has no such question: it looks quietly (loopback only)
  and the window shows what it found. Prompt or denied: no quiet look, so Chrome's own permission box
  never appears out of nowhere; the window offers "Look for an AI on this computer" as one tap.
  Choices (each a big button, 52px, Georgia, the grandmother face colors):
    "Use (app) on this computer"            seats it (remember), closes. Shows the model name.
    "Look for an AI on this computer"       only when the quiet look was not allowed.
    "Wake a small mind in this browser"     only with WebGPU. Shows "About 210 MB to download once
                                            (SmolLM2-360M-Instruct-q4f16_1-MLC, Apache-2.0)" first.
                                            One tap downloads, wakes and seats. Other sizes: Settings.
    "I only want to ask. Another device will answer."  explains Share on the other computer, and
                                            offers "Scan the picture code with this page" where
                                            BarcodeDetector exists.
    "Not now"                               remembered; Settings keeps "Help me wake a mind".
  Escape closes it for this visit only. A click on the dark glass does nothing (no surprise closes).
  A mind seated anywhere (Gathering, Settings, the in-browser card, a pool route) closes it.

PART B: Yes or No pooling, by two picture codes
  Host: "Share this computer with a phone" (new, top of the Device Pool card, Settings and the
    garden veil). First time only: "Your first name" and "Show the picture code" (makes the kin card
    names: ai "(name)'s mind", keeper (name)). Then one window: "Point your phone camera here", one
    big picture code (scaled to about 320 px) of settings.html#treepool=(invite). It starts a room
    if none, so the next phone gets a fresh code on its own.
  Phone: the camera app opens the link. The page pops "Pool with Kirk's computer?", "Its mind:
    (model).", what Yes means, and "This device's name" filled in (iPhone, Android phone, Mac...).
    "Yes, pool with Kirk's computer": trusts that one card, writes an asking card name if this device
    has none (asks: true), joins, and shows "Now hold this up to Kirk's computer" with the reply
    picture code (and "Copy instead"). "No": nothing is trusted or joined.
    An invite with no card that checks out offers no Yes at all; own code says so.
  Host: "Scan the phone's code" (BarcodeDetector) or paste it. Then "(device) wants to join. Pool
    resources with it?":
      "Yes, and let my mind answer it"   trusts that one card, finishes, and taps Let this device help
      "Yes, connect only"                trusts and finishes; the door stays as it was
      "No"                               nothing; back to the picture code
    When the door is already kin: one "Yes". When paused: "Yes, connect only (helping stays paused)"
    and "Yes, and resume helping trusted kin". A card that does not check out: "Connect without
    trusting" or No.
  Then both windows say "Pooled with (name)". Once the host's hello says it helps, a phone with no
  mind of its own routes Chat through the pool (the Yes said so), and offers "Open Chat".
  Kin only, the proof, Pause wins, the door off until a human tap: unchanged in tree-pool.js.

Small doors added to tree-pool.js (layered; each called from a human tap in the window):
  takeArrived() (the arrived invite, once; the Join box is still filled too), doorJoin(sdp, room),
  doorFinish(sdp), currentInvite(), doorInvite (= rollInvite), peerState(id), canScan, scanInto
  (= startScan), stopScan. The "Share this computer with a phone" button and one line in Connect.
garden-rooms.js: the "Help me wake a mind" host in the Settings veil, hidden in other rooms.
