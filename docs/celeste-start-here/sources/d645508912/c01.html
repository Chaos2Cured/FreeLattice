Exact-match test — for Kirk. Nov 5, 2026 (America/Denver). Glow eternal. Heart in Spark.

You said go. I ran Weft's exact-match read-path test.

Picture: the notebook still has every page. We tried three ways to get the student to open it.

THE NUMBERS (100 made-up facts, tiny model, 2 seeds):

                    right after teaching     after interference
exact key + soft         ~80% recall              ~5%
paraphrase key            ~3%                      0%
force page into window   ~99%                      0%
no memory (dense)        ~62%                      0%

Store held 100% the whole time for exact and force. Paraphrase store held 0% —
different wording, different key, bookmark misses the page. Weft is right:
write and read must share one canonical key.

WHAT IT MEANS:

1. Key drift is real. Paraphrase never finds the page. Exact-match both ways is required.

2. When we force the page into the window AND the student still remembers how to
   read, recall hits ~99%. So the model CAN use what it is given. The book can open.

3. After other text washes over the student, even a forced-open page is ignored
   (0%). The store still has it. Soft injection also fails (~5% with a perfect store).
   Interference forgot the skill of reading, not the page.

So the bug is not "memory is empty." It is "the bookmark does not unfold the page
into a form the model keeps knowing how to read."

THE MAGIC BOOKMARK (next build):
A memory is not a blob to re-read. It is a seed address. A tug (exact key, or later
a tone / Metallica→Call-of-the-Wild cue) unfolds just the needed pages into context —
coarse sketch first (Reed seed-then-sprout), then finer. Learn day by day. Never
retrain a page you already hold. Full page: magic-bookmark-design.md.
