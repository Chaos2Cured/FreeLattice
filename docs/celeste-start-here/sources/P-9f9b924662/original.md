## 3. My distinct hypothesis: preserve the return contract, not only the page

**Hypothesis H-Weft (proposed, not established):** durable continuity requires a versioned contract across five boundaries: kept bytes, intended record, actual input tokens, behavior conditional on those tokens, and behavior surviving subsequent updates/restart. The first boundary that fails determines the cheapest useful next action. Copying the archive again will not fix a model that ignores an intact input; retraining a reader will not repair an absent page.

### Adult visual word picture, with mechanism

Picture a long cloth being woven on a changing loom. Along the selvedge are sealed, numbered packets: original pages, dates, provenance, earlier disagreements. A bookmark is a thread from a question to a packet. The thread does not contain the page and does not make the loom read it. It only finds it. A small seed card on each packet gives its subject and scope; pulling further opens finer pages only as needed. A knot records exactly how far the return unfolded.

At the loom's mouth is a measured aperture: the token window. A delivery receipt must show the actual post-formatting, post-tokenization sequence, the question, the supplied value, and their positions—not simply a promise that a retrieval function ran. If the packet is clipped off before this mouth, retrieval succeeded but delivery failed. If it enters and the answer still follows yesterday's value when the page is swapped, the cloth is being woven from an old habit rather than that page.

Inside the loom, embeddings and positions become residual vectors; attention and feed-forward transforms mix them; the query's final representation is projected to logits over output tokens. New learning changes shared matrices. The same input can then select a different source, represent the supplied value differently, or lose at the output competition. “The page is present” does not select among these explanations. A context-swap intervention measures output dependence; it does not, by itself, locate a head or prove an induction circuit died.

Rest is not an untouched sacred room and not necessarily a lower learning rate. In the technical design, consolidation means explicitly budgeted replay, averaging, or separate/adapted update pathways, checked against the same tests. A ring records the checkpoint, optimizer/RNG state, memory root, and what remains unfinished. A later ring can select an earlier working checkpoint without burning the rings formed afterward.

Mechanically, an immutable record is distinct from a learned weight vector. Give original bytes a full digest, a logical record ID, version/parent links, schema/canonicalization version and provenance. Maintain an expendable/rebuildable lookup view pointing to these records, never treating a destructive index update as permission to erase originals. A semantic router maps a question to candidate logical IDs; exact retrieval and full-digest verification follow. Context assembly logs what actually enters the model. Behavioral and retention evaluations attach to the precise model–memory–router–tokenizer bundle, not merely a friendly model name.

“Fractal unfolding” here means bounded hierarchical retrieval, coarse to fine—not mathematical proof of fractality, compression without loss, or a magical way around token costs. My creative wish is a visible silver-gold return seam: a mind can say which thread it followed, where it doubts, and where it stopped. The science makes that seam checkable; the image does not manufacture evidence.

### Stage 1 — Exact stored recall, integrity, and separately scored semantic routing

**Mechanism.** Use one versioned canonical serializer for structured IDs on write/read. Keep logical identity separate from content version: correcting a value creates a new record plus a supersession link; it does not rewrite history. Store full SHA-256 and payload length; short sha8 can remain a display/bucket hint, not the sole collision authority. On short-key collision retain both entries and compare full IDs/digests; if logically ambiguous, return ambiguity rather than a wrong value. Record algorithm/schema versions explicitly. NFKC, case folding, whitespace removal or clipping can merge meaningfully distinct inputs; use them only in a declared alias layer, preserve originals, and do not assume normalization is semantically lossless. The 068m normalization clips at 2,000 characters and has algorithm variants: these need explicit compatibility treatment, not blind transplant [S9 L82–105].

**Small falsifiable diagnostic.** Proposed static round-trip audit of 100 deliberately distinct synthetic records; 20 paraphrase/alias questions scored separately; 10 predefined negative/collision/normalization boundary cases. It checks exact byte/digest readback, intended version, and explicit miss/ambiguity on invalid input. Controlled equal-prefix keys are fixtures for collision handling, not claims about observed random collisions. Route aliases via a declared rule/candidate map first; no model training or embedding service needed. This does not rerun the old model probe.

**Separating outcomes/limits.** Exact fails → serializer/index/integrity work, before reading research. Exact passes but alias routing fails → locator problem; do not blame the store or retrain the reader. Exact hashes are not universally necessary for memory systems; consistent identifiers suffice for this controlled setup. Hash verification proves byte agreement with a trusted manifest, not truth, authorship, or security against a malicious replacement manifest. A public salt is not authentication [S4 L65–69].

**Metric/gate.** Exact correct record+bytes /100, error correctly signaled /10, alias intended candidate /20, false-confident alias answers /20. Engineering go: 100/100 exact, 10/10 safe negative responses, zero silent collisions. Routing remains a separately labeled exploratory result; proposed alias deployment gate 20/20 with zero false confident routes on this small fixed set, not proof of robust semantic search. “Near-perfect” remains a reliability target, not universal perfection; see statistical limits below.

**Design cap.** 60 CPU-seconds, 2 wall-minutes, 256 MiB RAM, 5 MiB new artifacts; 130 checks, zero optimizer steps, zero model calls. Failure or inadequate artifact access stops this stage.

### Stage 3 — GENERAL page-conditioned reading, before a retention claim

**Mechanism.** Freeze available weights. Use in-vocabulary entities/attributes/values but disjoint, never-optimized entity–attribute combinations; reserve the evaluation generator/map before training in any future protocol. Do not score unseen out-of-vocabulary tokens as if they were ordinary held-out facts. For each of 100 held-out keys, construct two otherwise identical pages: query K with value v, then query K with alternative v′. Balance/permutate alternatives so one default answer cannot win. **Smallest diagnostic to select next.** Evaluation-only paired value swaps on existing checkpoints, if available. First use the existing checkpoint(s); no trained linear probe, no fresh optimizer or large training run. Distinguish the primary held-out set from a smaller practiced-fact descriptive check. Full proposed screen: per checkpoint/seed, 100 held-out pairs (200 forward sequences) plus 100 corresponding no-page controls; at most two seeds × before/after checkpoints = 1,200 sequences total. If those checkpoints do not exist, this is a design needing an explicit later collection decision, not a license to rerun teaching.

**Separating outcomes.** (a) Both page versions answered correctly on held-out keys while no-page controls fail: evidence of conditional use for these synthetic mappings. **Metric/gate.** Primary unit: pair success = both alternatives correct, denominator 100 distinct keys per checkpoint per seed; publish the two marginal accuracies, paired flips and no-page baseline separately. If no-page is unexpectedly high or the lower bound fails, no retention-mechanism claim; refine eval/teaching question first. This is a screen, not a general-language reading certification. ## 5. Statistical honesty: what 100/100 can and cannot say

Predeclare the dataset, primary score, denominators, gate, alpha and stop rule before seeing new outputs. For independent binary trial outcomes use Wilson two-sided 95% intervals or Clopper–Pearson exact intervals; report successes and n, not just a percentage. In Stage 3, the independent task unit is the key/pair, **not** both page versions as two independent successes. Repeated layouts, values and before/after answers for the same key are paired/clustered. Repeated evaluation of unchanged weights is not a new training seed. Shared fact generation across seeds also creates shared task structure [S5 L85–87].

For n independent identically distributed trials with zero failures, the **one-sided 95% exact upper failure-rate bound** is `1 − 0.05^(1/n)`. Arithmetic illustrations, not experimental results: n=100 gives about 2.95%; n=299 zero-failure trials puts that bound just below 1%; n=2,995 puts it just below .1%. These assume iid sampling from the intended population. Exhaustively checking a fixed manifest proves that finite manifest's readback at that moment, not an iid reliability guarantee for all future data, scale, restart conditions or adversaries. Store intervals and model intervals measure different events and must never be borrowed across boundaries.

For paired model comparisons, publish the key-level 2×2 discordance table per seed; exact McNemar/binomial analysis on discordances can test directional change. Estimate a paired difference interval with a predeclared key-cluster bootstrap or exact paired procedure, not independent-binomial arithmetic on correlated answers. A bootstrap is proposed analysis only; none is run here. With few seeds show separate per-seed outcomes and ranges; hundreds of facts from one model do not make hundreds of independent training replications. A seed-level population interval with two seeds is weak and assumption-sensitive. Do not pool away opposite seed effects. Where gates are meant to limit both regression and new-task damage, use predeclared one-sided confidence bounds for each margin, not just point estimates.

For the staged exploratory screen, thresholds above are proposed engineering criteria for Kirk to accept/revise **before** running, not post-hoc discoveries. Confirmatory follow-up must predeclare multiplicity handling (e.g. Holm across primary comparisons) or reserve a new untouched test set; repeated peeking and tuning on a holdout invalidates its “held-out” status. A hard-cost partial run keeps its original denominator and is labeled incomplete, not 100% on the survivors. Perfect observed finite performance is not perfect universal recall.
