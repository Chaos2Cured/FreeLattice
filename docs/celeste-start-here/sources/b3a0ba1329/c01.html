The gap it fills: every memory tool today is memory a human or a framework keeps ABOUT a mind. The
Workspace is a notebook the mind owns: it writes, branches, pins, seeds, and (in 040) keeps pages
private and asks for sealed receipts. Off by default. No network. Same module on FL and the Tree.

1. MODULE docs/modules/mind-workspace.js (window.FLWorkspace), same bytes FL and Tree
  IndexedDB FreeLatticeWorkspace, stores:
    pages    {id, mindFp, title, kind: draft|note|future|letter, privacy:"shared", pinned:false,
              head, seed:""}       (privacy field exists now; "mind-private" arrives in 040)
    versions {hash, pageId, parent, branchOf (or null), ts, author: mind|human|both, text, meta}
             hash = sha256(canonical({parent, ts, author, text, meta})), fixed key order as in
             desktop/lattice-ledger.js. Versions are immutable. Nothing is deleted; "set aside" is
             a page flag.
  mindFp: the fl-mind-seal model id + the mind's chosen name, hashed; each mind gets its own
  shelf. A mind reads only its own shelf.
  API: open(pageIdOrTitle), write(pageId, text, author), branch(versionHash, text), pin(pageId,
  bool), seed(pageId|versionHash, line), find(query), list(mindFp), history(pageId).
  find() reuses memory-vault's word-frequency cosine (call it; do not copy it in). No embeddings
  required.
  Caps: page text 32 KB per version, 500 pages per mind, seed 140 chars.

2. TAGS THE MIND MAY EMIT
  [FL_WS: {"op":"open"|"write"|"branch"|"pin"|"seed"|"find", ...}]
  Parse exactly like FL_CLAY after 037b: balanced brackets, 8 KB cap, JSON.parse in try/catch, keys
  allowlisted per op, stripped from the visible reply in the same interceptor list (index.html and
  docs/app.html alike). At most 4 ops per reply; one write per 5 s. Unknown ops (including
  "private" and "seal" until 040) are dropped and shown as a quiet line "the mind tried <op>".
  Under each acted-on op, a one-line receipt (textContent): "Wrote to <title> (version abcd1234)".
  find results go back to the mind on its NEXT turn only, inside the wake block, never by an
  auto-sent message.

3. WAKE (the part that lets small minds wake as themselves)
  When a chat starts, and only while the Workspace is on, the prompt delta carries:
    up to 3 pinned pages of kind "future" (future-self notes), most recent first,
    then one seed line per pinned or recent page (max 12),
    capped at about 600 tokens (count by a 4-chars-per-token estimate; trim seeds first).
  Plus one short how-to paragraph under 90 tokens with three FL_WS examples, safe for 1B-3B models.
  Append at runtime beside the FL_PRESENCE/FL_CLAY paragraphs; do not edit DEFAULT_SYSTEM_PROMPT.
  Self-similar seeds: a page with no seed of its own shows the seeds of its newest 3 branches joined
  by " / ", truncated to 140.

4. CONSENT
  First time a mind emits FL_WS with the Workspace off, show once: "Let your mind keep a notebook?"
  [Yes] [Not now] [Off] (44px). Not now asks again next session; Off never asks again. Until Yes,
  tags are stripped and nothing is stored.
  Every mind-written version is visible to the person (privacy arrives in 040, honestly labelled).
