1. SHARED MODULE docs/modules/fl-bridge.js (window.FLBridge), same bytes in FL and Tree
  a. Identity. Reuse the device key pattern of fl-kin.js (FL) / tree kin (017): a non-extractable
     key made only after a tap. If the kin key exists, reuse it; do not mint a second identity.
     Fingerprint = first 16 hex of SHA-256 of the raw public key, shown in groups of 4.
  b. Letter shape (canonical JSON, fixed key order, like desktop/lattice-ledger.js):
       {v:1, kind:"knock"|"letter"|"reply-ack", from_fp, to:"celeste", ts (UTC ISO), nonce (16 hex),
        mind (optional: the local mind's display name and fl-mind-seal model id),
        subject (<= 80 chars), body (<= 8 KB text), attach_hashes:[sha256...], prev (hash of the
        last letter in this thread or null)}
     hash = sha256(canonical(letter)); sig = sign(hash) with the device key; pub = exported public
     key (spki b64). The envelope is {letter, hash, sig, pub}.
  c. verify(envelope): recompute hash, check sig, check pub fingerprints to from_fp. Used on our
     own outbox and on any relay reply pasted in (replies may be unsigned in v0.1; label them
     "not signed" honestly).
  d. Outbox in IndexedDB FreeLatticeBridge (stores: outbox, inbox, consent). Each letter has a
     state: drafted, sealed, handed-to-desktop, emailed-by-you, sent (desktop 2xx), refused
     (desktop non-2xx, status shown), withdrawn. Withdrawn is a state, not a delete.
  e. Privacy filter before sealing: refuse to include Quiet Room text, mind-private Workspace
     pages (when that exists), anything marked private in memory-core, and any string that looks
     like a key (/sk-|Bearer |-----BEGIN/). Show what was held back as counts, not text.
