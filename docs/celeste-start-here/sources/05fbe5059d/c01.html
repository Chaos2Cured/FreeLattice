3. WHAT THE DIFF DOES (4 files, +133 / -2; both removed lines are kept as comments)
----------------------------------------------------------------------
a) bridge/proxy-core.js and desktop/main.js share one table, OLLAMA_DOORS, and one
   ollamaDoorOpen(method, path). It sits between "// v-narrow-door-v0.1: only these Ollama
   doors" and "// end v-narrow-door-v0.1 table". The smoke keeps the two copies equal.
   - Open: GET/HEAD / and /api/tags; GET /api/version, /api/ps, /v1/models.
   - Also open: POST /api/chat, /api/generate, /api/show, /api/embeddings, /api/embed,
     /v1/chat/completions, /v1/completions, /v1/embeddings, /api/pull.
     Pull stays open for the app's own download button, and Kirk will decide on it.
   - Everything else gets 403 "This door only lets chat through": delete, create, copy,
     push, blobs, and paths with tricks like /api/chat/../delete. Matching is exact.
b) Bridge: the door check runs after the origin allowlist and "Yes, help". Exports the
   table and the check.
c) Desktop local server:
   - The star CORS line is replaced. ACAO is now sent only for the app's own origin,
     http://127.0.0.1:<serverPort>.
   - The old line is kept as "before v-narrow-door-v0.1: ... '<star>'". The star is spelled
     out, so the bare-star lock stays at 0.
   - /ollama requests from any other Origin get 403 "Only this app may use its local AI",
     then the door check runs.
   - The app itself uses same-origin /ollama (no Origin header, or its own), so it keeps
     working. The live freelattice.com page never calls port 45678.
d) docs/scripts/smoke-narrow-door-v0.1.js (new): the table is equal in both files; good
   doors open, bad doors and path tricks closed; the bridge 403s before the proxy; the
   desktop has no star line and has the foreign-origin refusal.
e) Ledger entry with your placeholder.
People with the Bridge or the desktop app installed only get this after a rebuild or
reinstall. Mention that in the PR body.
