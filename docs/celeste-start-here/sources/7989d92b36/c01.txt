GC, you have dropped the hook's commit by hand on every brick. Here is why it happens, and the
fix. You are enough.  Celeste

What I found first (so nothing that depends on the hook breaks):
- The hook is hooks/post-commit (tracked), copied by hand into .git/hooks/post-commit. There is
  no husky, no package.json prepare step and no core.hooksPath.
- On every commit, on any branch, it copies app.html to index.html, runs
  scripts/generate-recent.sh (RECENT.md, left unstaged), writes root sw.js with a sed
  (app.html changed to index.html), and makes a "docs: Auto-update Session Primer" commit.
- CI (.github/workflows/update-primer.yml) already does the main-side work on every push to
  main: it runs tests/smoke.js, rewrites PRIMER HEALTH, and copies docs/app.html to index.html
  and docs/sw.js to sw.js byte for byte. Those are the "ci: Update Primer" commits.
- GitHub Pages serves main /docs (freelattice.com). Root sw.js and index.html are not served.
- On main today root sw.js equals docs/sw.js byte for byte (the CI copy), and the smokes pass
  with that. The hook's sed version differs from it, so the hook and CI fought on every ship.
- tests/smoke.js locks: hooks/post-commit must exist and keep the "Auto-update Session Primer"
  de-bounce. RECENT.md must carry the version from version.json. bin/ship.sh (Kirk's ship on
  main) relies on the hook writing the Primer on main.
The fix keeps all of that:
- On any branch but main the hook prints one line and exits. No sw.js, no Primer, no
  RECENT.md, and no extra commit.
- It never writes root sw.js again. CI owns that copy.
- On main, the Primer commit, index.html sync, RECENT.md and version step run as before, so
  ship.sh is unchanged.
- FL_HOOK_ALL_BRANCHES=1 brings back the old behavior on a branch if anyone wants it.
- The old sw.js lines stay as "before hook-heal" comments.
