1. WHY
----------------------------------------------------------------------
Hypha walked the live Pool card (#176) today, 11:01 to 11:20 MDT. HOLD, as care.
With the share door already open, the card says "Off. Nothing from this device is
offered until you tap." Hypha called FLShareDoor.admit with a verified stranger's key:
open lets it past the kin gate. So the card says Off while any connected, verified
peer can use this computer's AI. 016 heals the helping line only. This heals the
not-helping line, the same way, and the two should merge together.

What admit() really does (fl-share-door.js, read, not changed):
  open  -> any connected, verified peer may pass (then caps, plug, signature)
  kin   -> trusted kin only (granted, not revoked); with zero kin, no one
  pause -> no one ("paused-or-off")
  off   -> no one
  The pool flag (fl_pool_helping) only gates hellos. The share door is the real gate.

The not-helping line now reads the door:
  open            -> "Not helping in the pool, but your share door is open: people you
                     connected with can already use this computer's AI. Tap Only trusted
                     kin to narrow it." plus the same "Only trusted kin" button 016 adds.
  kin, kin > 0    -> "Not helping in the pool, but your share door lets your trusted kin
                     (N) use this computer's AI. No one else."
  kin, zero kin   -> "Off. Nothing from this device is offered until you tap. Your share
                     door is set to trusted kin only, and you have no trusted kin yet."
  pause           -> "Off. ... until you tap. Your share door is paused too."
  off / no door   -> "Off. Nothing from this device is offered until you tap."

Pause wins visibly (the queued heal in GROK_NEXT_ORDER.txt):
  Door paused + tap "Let this device help" -> nothing changes yet. The card asks:
  "Your share door is paused. Helping would resume it for trusted kin only, not for
  everyone. Resume for trusted kin?" [Yes, resume for trusted kin] [Keep it paused].
  FLPool.letHelp() called without { resume: true } returns
  { ok: false, reason: 'door-paused', ask: true }, so code can never resume it silently.
  Door off -> kin on the tap, as in 014 (newcomer path, one tap).

Plain words on the card (a short list under the note):
  Whose AI: this computer's own local AI, the minds listed under This device below.
  What is shared: questions from verified peers you connected with run on that AI, and
    the answers go back to them.
  Hellos go to verified peers only and carry this device's rough memory, cores and model
    names. No chats, no keys.
  Power: answering uses this computer's power and battery. Stop helping pauses the whole
    share door.
  [ ] Only help while plugged in (some browsers cannot tell; then this does not stop help)
      one tap, the same fl_share_door_plugged_only the share door card uses.
  While helping with kin and zero kin: "Trusted kin only, with no trusted kin yet, means
    no one can be helped yet. Tap Trust this AI on a connected person's card above."
  The empty line drops "Connect them on Community first" (the card lives on Community):
    "Connect them with Create Connection, higher up on this page, then ..."

A real card: fl-pool.js adds one <style id="flPoolStyle"> (textContent, same pattern as
fl-kin.js KIN_CSS) using FL vars (--bg-card, --border, --radius, --shadow, --accent).
Buttons are 44px tall (Hypha measured 19px). "Let this device help" and "Yes, resume"
are the gold primary. Under 480px buttons go full width. No app.html change.
