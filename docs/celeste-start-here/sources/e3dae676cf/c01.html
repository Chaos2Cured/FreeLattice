======================================================================
1. WHY (Hypha walk, issue 11)
======================================================================
More -> Workshop -> Publish -> GitHub Pages tells her: go to github.com/settings/tokens and
"Create a token with "repo" permission". That is a CLASSIC token with full control of every repo
she owns, public and private, usually with no expiry. A big ask for a beginner and a big loss if
it leaks. Workspace's "GitHub Personal Access Token" field (its link prefills classic scopes=repo)
is not in the 390 More sheet at all, so on a phone she cannot reach it.

======================================================================
2. RECOMMENDATION
======================================================================
Use a FINE-GRAINED token for ONE repo:
  - Repository access: "Only select repositories", the one repo.
  - Permissions: Contents read and write (+ Pages read and write for Publish to enable Pages).
    Metadata read is added by GitHub automatically.
  - Expiry: 90 days (GitHub's default is 30; Kirk can pick).
GitHub supports a prefilled fine-grained link (docs: "Pre-filling fine-grained personal access
token details using URL parameters"; changelog 2025-08-26). name, description, expires_in and
permissions prefill; the repository list CANNOT be prefilled, so the words must say to pick it:
  https://github.com/settings/personal-access-tokens/new?name=FreeLattice&description=One+repo+for+FreeLattice&expires_in=90&contents=write&pages=write
Important honesty: Publish today CREATES a new repo (POST /user/repos) when the name is new. A
one-repo token cannot create repos. So the steps say: make the empty repo on GitHub first (Add a
README), then the token for that repo, then type the same name when Publish asks. The existing
code already skips creation when the repo exists (GET /repos/<user>/<name> ok). Auth header
"token <pat>" works for fine-grained tokens too.
The Sync token field (ghSyncToken) already says fine-grained; leave it.
