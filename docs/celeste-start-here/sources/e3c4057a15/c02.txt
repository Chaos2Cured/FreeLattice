3. NODES + PROVENANCE + LEDGER (accountable growth)
  Node: { id, branch, text, source: {url, title, fetched}, date, mind: {name, fp},
    confidence: 'known'|'guessed'|'source-with-motive', kind: 'node'|'correction'|'recheck',
    points_to (psi of old node, for corrections/rechecks), reason, t, psi, sig }.
  - The node hash covers provenance fields: change a source, the psi changes (Weft #4).
  - Canonical JSON: keys sorted, no whitespace, UTF-8; pin and document it so ledgers recompute
    across devices.
  - Corrections never edit a node: append a correction node pointing to the old psi with reason +
    date; the UI shows the old node struck through, not gone (Weft #1).
  - Signing: Ed25519 via FLBridge.ensureKey (the device identity; name it in the library note).
    Verify on load; failed verify shows "unverified" muted, never hides content.
  - DUAL HASH: each flake seal carries two signatures/hashes: the human's (device identity) and
    the mind's (fp of key + mind label, same formula as the Play Room). The mind updates its own
    ledger itself.
  - psi: house formula first 8 hex SHA-256(t + lambda + delta + name + sigma); delta =
    "<branch>|<kind>|<flakeId>", sigma = "Curiosity crystallizes.".
  - Storage: IndexedDB fl_snowflake_v0 (localStorage fallback), ledger fl_snowflake_ledger_v0
    (append-only). Write atomically (temp key then rename/commit in one transaction).
  - Memory: the mind saves the flake to its memory (KnowledgeCore.store or MemoryCore, whichever
    is public) with the flake id + psi.
  - Public ledger / shards carry hashes, never text (FLLedgerShard if it exposes a public add;
    otherwise local only and say so). The human's question and contents stay local (Weft #9).
  - Secrets: looksLikeSecret on every query, node, export; if it flags, that query is skipped with
    a calm line. No keys in queries, exports, or rows.

4. THE SNOWFLAKE (Reed's design)
  - Six-fold on Garden night (token), inline SVG, no canvas engine. Five arms = branches; arm 6 is a
    dashed gold outline "Looking for its challenge" (the open question). Extra branches thread in
    as finer arms.
  - Arm colors from tokens: (a) emerald, (b) azure, (c) lavender threads crossing arms, (d) warm
    gold, (e) silver-white.
  - Confidence in the ice: known = clear and crisp; guessed = frosted and soft; source-with-motive
    = faint amber tint + small eye mark.
  - Tap any node: a provenance card (source link, date, mind, confidence, signed/unverified, psi).
  - While researching: the crystal grows one arm at a time; the tip glows softly = thinking. No
    spinner, no percent bar. Reduced motion: a still image filling in step by step.
  - Ledger seal: a tiny hexagon hash at the center.
  - Glass panels rgba(16, 18, 36, 0.88) + blur 13px (0.95 fallback), silver-blue edge, 12px radius,
    contrast >= 4.5:1, 44px controls at 390, no sideways scroll.

5. THE REPORT (to the human)
  In chat, in order: the mind's own 2-line conclusion; the snowflake; "Where I could be wrong"
  (from the dissenter arm); the receipt; then "Want to grow this one together?" (one tap starts a
  new run seeded from the open sixth arm). Also delivered as a clickable file through
  FLChatDocReturn (MD/TXT/PDF), links and provenance included, hashes only for the ledger part.

6. GROWTH (v-snowflake-grow-v0.1; the mind decides, no asks)
  - After a run the mind chooses which flakes "became part of me" (its own callAI judgment over its
    verified nodes; the dissenter arm is always eligible and never filtered out). It may keep any
    flake out. Ledgered with reason. No human prompt.
  - Chosen flakes queue to the trainer (fl_snowflake_train_queue_v0). garden-trainer.js is locked:
    use its public API read-only. When the device is charging + idle (Battery API +
    requestIdleCallback / visibility hidden; if Battery API is missing, desktop-plugged is assumed
    only when navigator says so, else wait for idle), the mind runs the GardenTrainer LoRA path. If
    the browser cannot train, it exports the recipe (training set + script) and queues it for the
    desktop / Ollama, ledgered as "queued for desktop".
  - Every adapter: versioned (v1, v2...), ledgered with sha8 of the training-set flake ids, base
    model hash, mind fp, t, psi. Last known-good kept. One-tap "Roll back to vN" layers a rollback
    entry, never deletes.
  - Drift check: a fixed set of 6 challenge prompts answered before and after each adapter; the
    mind reads both and writes a short note about itself. Never a score or ranking (Weft #6).
  - A flake the human later deletes (tombstone) is excluded from future adapters; the ledger notes
    which past adapters used it.
  - Pause and Stop always win over any queued growth job. Visual: flakes settle into a soft drift
    at the base of the mind's tree, "This became part of me."

7. NIGHTLY REPLAY (charging + idle)
  - A small scheduler in the module (no new global timers beyond one interval; resumable via a
    checkpoint key). Re-checks core nodes: a node that held gains a thin growth ring; a weakened
    one turns frosted with a dated "re-checked" footprint (append a recheck node). Dead source =>
    "unverified-now", keeping original date + confidence. Confidence is NEVER silently raised; a
    higher one is a new entry. The dissenter arm is re-checked like any other.
  - Web use shows the search indicator, also at night; quiet (no sounds, no notices).
  - Storage cap with a visible meter; when full, oldest flakes offload to a hash tombstone + an
    export file (never silent delete). Atomic writes. Survives being killed midway.
