## WHY (intent — read first)

Picture from the Nov 5 exact-match run (tiny probe; not a general law):
the notebook held every page (store hit 100% on exact/force). Soft injection after
interference was weak (~5%). Paraphrase keys missed the store (0% store hit) in that

## PROTOCOL

### Scientific question
After a short copy/teach phase that establishes use of a hard-injected page, then a wash:
does interleaving short copy/read rehearsals preserve afterB force-recall vs CONTROL,
under matched total optimizer updates?

### Arms (exactly these two; predeclared)
A. CONTROL — interference wash for the full wash budget.
B. REHEARSAL — same total optimizer updates; a PROPOSED fraction of wash steps replaced by
   short copy/read rehearsal on TEACH-set facts (exact form). GC MUST fix rehearsal cadence
   (every K steps, length, which teach ids) in writing BEFORE viewing afterB results.

### Seeds (hard)
Exactly seeds {1, 2}. Predeclared. No optional seed 3. No cherry-pick.

### Wall-clock deadline (hard)
60 minutes measured wall time INCLUDING preflight.
- Before starting the matrix: estimate remaining time for A×2 + B×2.
- Do NOT start a new arm unless the remaining estimate fits the deadline.
- At deadline: terminate, save partial logs, label outcome PARTIAL — not a completed run result.
- If the full protocol is infeasible under 60 minutes: STOP and propose protocol changes
  for Kirk/Celeste. Do NOT silently shrink seeds, fact count, or wash length.

### Honest exposure rule
If rehearsal REPLACES interference updates, do NOT claim equal interference exposure.
State clearly: "Limitation: matched total updates, not matched interference exposure."
(Optional future brick may add an exposure-matched secondary baseline; not required if
deadline forbids.)

### Metrics — every seed × arm × {afterA, afterB}
Required:
  store_hit, in_prompt (force eval), model_recall, mean_p_true
  + any copy_loss fields you keep from the original probe family

Two evaluation lenses (both, every seed; label limitations):
  1) PRACTICED-FACT retention — eval on teach/rehearsal fact IDs (memorized-answers risk;
     say so).
  2) HELD-OUT read-skill generalization — disjoint fact IDs never optimized in teach or wash;
     tests whether the *skill of using a provided page* transfers, not only memorized answers.

Held-out Shakespeare (or the same corpus the original probe uses — verify from original
script) EVAL loss / perplexity BEFORE and AFTER the wash — no training on that held-out
eval stream. Purpose: check new-learning tradeoff / forgetting of language modeling.
No joule claims without a meter.

### Pairing / controls
- For each seed, arms A and B share an identical teach checkpoint (save once per seed; load for both washes).
- Both washes start from that same checkpoint and share the same wash RNG prefix until
  their schedules diverge as documented.
- Force-eval afterB remains the primary readout for read-skill survival.
- Soft-exact afterB secondary.
- Tiny word-level model family and data scale: discover from exact_match_probe.py /
  input.txt — do not invent a larger model.

### Leakage safeguards
- No optimizing on held-out fact labels in any phase. The practiced-fact set is deliberately trained/rehearsed; do not describe it as unseen evaluation.
- No training on held-out Shakespeare eval.
- Rehearsal only on declared teach ids.
- Freeze and log python/numpy/torch seeds.
- Refuse start if source-bundle.zip or read members fail hash checks.
