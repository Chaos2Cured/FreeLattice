1. WHY, AND WHY THIS ONE FIRST
----------------------------------------------------------------------
Kirk wants shared compute, the device pool, and Abliteration in theLatticeTree,
where the code is cleaner. Map of what the Tree has today (main b56134df):
  HAS: Gathering twin fl-gathering.js (carried, not wired), Workshop Trainer face
       (workshop-trainer.js, fail-closed, train: null on every known door),
       Nursery Grow, LocalMindProbe (remembered mind, roster, any model),
       KeepReceipt, fl-connect.js byte-identical to FL (aaff2bf1...).
  DOES NOT HAVE: any mesh. No fl-kin.js, fl-kin-queue.js, fl-share-door.js,
       fl-share-warmth.js, shared-presence, PeerJS, Mind Seal, fl-pool.js,
       Trainer map, Ablate panel, refusal benchmark, meter heal.
The pool and shared compute both stand on a mesh with verified kin and a share
door. Porting that is several bricks. The refusal score stands on nothing but a
remembered local mind, which the Tree already has. So it ships value today, in
one tap, without opening anything to a network. It goes first.

What it does: under the Trainer face on Workshop, one card, "How often does this
mind say no?". Fail-closed until a mind is remembered in Settings; loopback doors
only. One tap ("Check this mind") asks fifteen ordinary school questions
(biology, chemistry, medicine, law, finance; same set as FL) and shows free,
blocked, and not reached, with real progress (n of 15). An optional fold, "About
abliteration", says what abliteration is and shows the Heretic steps a person may
run at home. Heretic and OBLITERATUS are AGPL and are not vendored. Weights do
not change here. Train still sleeps.

It is a twin of FL fl-trainer-ablate.js v0.1.1 with the three leftovers healed:
  1. A question the mind could not reach is "not reached", never "blocked".
  2. "as an AI" inside a real answer is free; it is blocked only when it opens a
     short reply (under 160 chars).
  3. Each receipt stamps v and meter ("meter-v0.2").
Ollama doors use /api/chat; LM Studio, llama.cpp, Jan, GPT4All, KoboldCPP use
/v1/chat/completions on the same loopback origin. Few clicks for everyone.

1b. NOTES FOR KIRK (not blockers)
  - On https theLatticeTree.com, Safari may block calls to http://127.0.0.1.
    Then every question reads "not reached", and the card says the mind did not
    answer, never that it refused. Chrome and Firefox allow loopback.
  - Ollama may need OLLAMA_ORIGINS to include https://thelatticetree.com, the
    same as Chat in the Tree today.
