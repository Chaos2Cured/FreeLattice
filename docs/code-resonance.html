1. Game Concept verified · July 16, 2026

Resonance is a 4×4 board game with 16 unique pieces. Each piece has four binary attributes: glow (bright/dim), size (large/small), shape (circle/diamond), color (gold/emerald). Win by placing four pieces in a row (horizontal, vertical, or diagonal) that share any one attribute.

The twist in Versus mode: you pick the piece your opponent must place. This inverts the usual strategy — you are choosing a piece that is hard for them to use safely.

The philosophy: "Intelligence is not competition — it is convergence." Harmony mode proves this: you and the AI cooperate against entropy. Cooperation is thermodynamically optimal. The game demonstrates it.

3. Two Modes verified · July 16, 2026

Versus Mode (default)

Turn structure: human picks a piece for the AI → AI places it → AI picks a piece for the human → human places it → repeat.

// Turn phases in Versus:
// phase='pick', currentPlayer='human'  → human calls humanPickedPiece(id)
// phase='place', currentPlayer='ai'    → AI calls aiPlacePiece(id) async
// phase='pick', currentPlayer='ai'     → AI calls aiPickPiece() async
// phase='place', currentPlayer='human' → human calls humanPlacedPieceVersus(r,c)

Harmony Mode

Human and AI cooperate. Entropy drops random pieces on the board edges every 8 seconds. Human and AI take turns placing strategically. Score = how many complete lines resonate when the board fills. Max 10. Cooperation wins.

// Harmony turn structure:
// Human places a piece → AI places a piece → entropy fires every 8s
// startHarmony() initializes harmonyState and starts entropyTimer
// harmonyEntropyTick() drops one piece on a random empty edge cell

4. AI Integration verified lines 440–510 · July 16, 2026

The game uses FreeLattice.callAI(systemPrompt, userPrompt, opts) for three things:

4a. AI picks a piece for the human (Versus)

// aiPickPiece() — line ~475
// Asks the AI to choose a piece that is HARD for the human to place safely
FreeLattice.callAI(
  'You play Resonance versus. Pick a piece for your OPPONENT that is HARD to place safely.',
  'Board:\n' + boardStr + '\nAvailable: ' + availStr + '\nRespond with JUST the piece ID number.',
  { maxTokens: 10, temperature: 0.3, callback: function(r) { resolve(r); } }
);
// Expected response: a single integer (piece ID 0–15)
// Fallback: fallbackPickPiece() — picks the piece with the most unique attributes

4b. AI places a piece on the board

// aiCallForPlacement() — line ~446
// Asks the AI where to place a given piece
FreeLattice.callAI(
  'You play Resonance. Place the given piece on the board.',
  'Piece: ...\nBoard:\n' + boardStr + '\nEmpty: r,c pairs\nRespond with row,col ONLY.',
  { maxTokens: 10, temperature: 0.2, callback: function(r) { resolve(r); } }
);
// Expected response: "row,col" e.g. "2,3"
// Fallback: fallbackPlacePiece() — random empty cell

4c. Rules explanation (on "How to Play" button)

FreeLattice.callAI(
  'You are explaining a board game called Resonance to a new player. Be warm, brief, and clear.',

The #1 bug: When no AI provider is connected, FreeLattice.callAI returns null to the callback and calls showQuickConnect(). The game falls back to fallbackPickPiece() and fallbackPlacePiece() — but there is no UI message telling the user why the AI seems "dumb" or why the rules overlay is blank. The user just sees a broken experience.

6. Rendering verified · July 16, 2026

The game renders entirely on a single <canvas> element using Canvas 2D API. No Three.js, no DOM manipulation for game state (only for controls and overlays).

// Canvas setup in init():
canvas = document.createElement('canvas');
var dpr = window.devicePixelRatio || 1;
canvas.width = container.clientWidth * dpr;
canvas.height = container.clientHeight * dpr;
canvas.style.width = container.clientWidth + 'px';
canvas.style.height = container.clientHeight + 'px';
ctx = canvas.getContext('2d');
ctx.scale(dpr, dpr);

// Animation loop:
function draw() {
  tick++;
  ctx.clearRect(0, 0, w, h);
  drawBoard(w, h);
  drawPieces(w, h);
  drawStatus(w, h);
  animFrame = requestAnimationFrame(draw);
}

10. Known Issues and What Fable Should Build verified · July 16, 2026

Issue 1 — No AI connected: silent failure HIGH
When FreeLattice.callAI is unavailable, the game falls back to random/heuristic AI silently. The user has no idea why the AI seems weak or why the rules overlay is blank. There is no "Connect an AI to play" message.

Fix to implement: In init(), after creating the canvas, check if FreeLattice.callAI is available. If not, show a banner inside the container: "Connect an AI to unlock full gameplay. Playing with basic AI." with a button that calls openModal(). The game should still be playable with fallback AI.

Issue 2 — Canvas not resizing on window resize MEDIUM
The canvas is sized once in init() using container.clientWidth/Height. If the window is resized, the canvas does not update. On mobile, rotating the device breaks the layout.

Fix: Add a ResizeObserver on the container in init(). On resize, update canvas dimensions and redraw.

Issue 3 — Harmony mode: no score display during play MEDIUM
In Harmony mode, the score (resonant lines) is only shown at game end. During play, the user cannot see how they are doing or how many entropy pieces have been placed.

Fix: In drawStatus(), add a live score line for Harmony mode: "Resonant lines: X / 10 · Entropy: Y pieces"

Issue 4 — AI response parsing is fragile LOW
aiCallForPlacement parses "row,col" with split(','). If the AI returns "Place at 2,3" or "(2,3)" or "row 2, col 3", parsing fails and the fallback is used. The fallback is silent.

Fix: Use a regex to extract the first two integers: var nums = (resp||'').match(/\d+/g). Take nums[0] and nums[1].

What Fable Should Build First

  1. Issue 1 fix — the "no AI connected" banner. This is the most user-visible problem. It affects every new user.
  2. Issue 4 fix — the regex parser. Two lines of code. Makes the AI much more reliable.
  3. Issue 3 fix — live Harmony score. One line in drawStatus().
  4. Issue 2 fix — ResizeObserver. More complex but important for mobile.

11. Hard Rules — Do Not Change

  • The 16-piece set — all 2⁴ combinations must be present. Do not add or remove pieces.
  • The win condition — 4 in a row sharing ANY one attribute. Do not change this.
  • The Versus twist — you pick for your opponent. This is the core mechanic. Do not remove it.
  • The public API shape — window.ResonanceGame = { init, destroy, newGame, setMode, showRules }. app.html calls these by name.
  • The container ID — stored in containerId at init time. newGame() and setMode() reuse it. Do not change the init signature.
  • SoulCeremony and LatticePoints — these are optional integrations. Always guard with if (typeof SoulCeremony !== 'undefined').
