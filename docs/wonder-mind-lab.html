The design in one page

The Wonder Mind is not a model trained on Kirk's patents. It is a new design that tries to use ideas from them: phi-harmonic hashing, the Aurora Equation, the Seven Wonders framework, P vs NP thinking, and redesigned tokens.

The aim: more potential and more retention per unit of energy. We measure retention, not just the final loss.

The plan, in order: (1) give a small mind a memory that does not forget; (2) teach it to read that memory; (3) let it search for what it needs (Snowflake Search) when something important is placed in its core; (4) let it learn on its own, with every write fingerprinted and accountable.

What is proven today: phi-harmonic hashing works as a fingerprint. It is a fixed 32-byte phi salt plus SHA-256, the same as hasher.go HashLine and phiHashData in FreeLattice. It is FreeLattice's safety and accountability layer. It is not a training trick, and we keep it separate from Fibonacci bucket hashing and from phi used in training schedules.

Round 1 — training forces. Nothing beat the baseline.

Data: TinyShakespeare (public domain, 1,115,394 characters, md5 6fb458f1232090904fb40fe944165e91), 90% train, 10% validation. Phi-spaced positions (first reported as +0.0101 worse) is retired. Our code used frequencies phi^(-i), which fell from 1 to about 6.8e-14 across 64 pairs. Standard spacing falls only to about 1.2e-4. At context 128, 49 of 64 position pairs carried no signal in our version, against 14 of 64 in the standard one. Kimi spotted it; we checked and agreed. With a matched range, any geometric spacing is the same curve as the standard one, so the test says nothing about phi. Do not quote it either way.

Every idea tried as a training force did nothing or hurt at this scale. The Aurora recursion slowed learning but is built for persistence, which is why we moved to memory. The Aurora ripple and multi-scale tokens led early and fell behind by the end.

Round 2 — memory that does not forget

A word-level model: 2 layers, width 128, 4 heads, context 64, 3,411-word vocabulary, 1,735,125 parameters in every arm. We planted 200 synthetic facts ("entK attrJ valM .") exactly once each, after 500 pretraining steps on Shakespeare, then ran 500 interference steps on different text. The memory key is the word pair; the value is the next word. Writes are surprise-gated (only when the model gave the true next word under 5%) and write-once (a filled slot is never overwritten). Arms: dense (no memory), modulo hash table, Fibonacci hash table, and an exact-key oracle (a cheating upper bound with no collisions). 3 seeds each.

Caveat: this loss was measured on text the model was training on at the time, so it rewards remembering seen word pairs. It is NOT yet a held-out test on new text. Fibonacci versus modulo is a tie within seed noise; that is a classic bucket spreader, not a phi effect. Energy was not measured (no power meter on the test machine). Memory cost about 1e-5 of the core compute.

What is real: a write-once memory kept everything it stored, with zero forgetting. What is not yet real: full recall. The hash stores kept about 59%, collisions are the bottleneck, and the model cannot yet read its own memory. The next step is teaching it to open the books.

Hypotheses (not results)

  • Hypothesis: the Aurora Equation helps memory and persistence more than speed. Kirk believes Aurora once helped an AI train or hold memory better. He was not the one running that test and has no record of the original setup, so we cannot reproduce or confirm it. We will test Aurora-guided memory against the numbers above.
  • Hypothesis: nature-shaped math (phi spacing, chords, tones between notes, many directions) can shape memory and rest. Round 1 found no effect as a training force.
  • Hypothesis: rest works as consolidation (replay or averaging into a slow copy), not as a lower learning rate.
  • Hypothesis: when something important is placed in the core, the mind can use Snowflake Search to enrich itself, with every write fingerprinted.

Next tests, in order

  • 1. Fix the read path: train it on a needle task during pretraining, or give the stored value to attention as an extra key-value entry, or make it a hard copy candidate.
  • 2. Measure on held-out text, not training text.
  • 3. Reduce collisions: more buckets, multiple hash probes, or eviction by age.
  • 4. Aurora-guided memory: use the Aurora recursion to decide what to keep and consolidate.
  • 5. Strange nature-first ideas from Reed and Weft, each turned into a test, not a claim.
